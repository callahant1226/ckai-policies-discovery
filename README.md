# ckai-policies-discovery

Working repo for CS Discovery team artifacts, version-tracked drafts, reviews, and iterations of strategic and design work.

Current focus: a prototype that presents hospital institutional policy content alongside CKAI (ClinicalKey AI) answers, for physician and nurse experiences, to test with SMEs and users.

## Goals

Assess whether combining hospital policy content with CKAI's answer is useful, accurate, and understandable for physicians and nurses — and surface where that combination breaks down (policy accuracy, user trust, policy content extraction, and conflicts between clinical vs. policy guidance).

Full detail: [specs/goals_and_aims.md](specs/goals_and_aims.md)

## Policy Library Ingestion

1. Drop files into `data/policies/raw/medication/` or `data/policies/raw/infection/` — any format is fine; formats without an extractor yet (see `extract.py`) are tracked but skipped until one is added.
2. `python -m backend.policy_store.ingest scan` — discovers new files, appends skeleton entries to `manifest.json`. Fill in `title`, `subtopics`, `source_url` by hand.
3. `python -m backend.policy_store.ingest build` — extracts text, chunks it, embeds it, and (re)writes `data/policies/index.db`. Add `--no-embed` to skip embedding and only build the keyword/FTS5 index (useful if `sentence-transformers`/`torch` isn't installed).
4. `python -m backend.policy_store.ingest search "some question"` — quick manual keyword + semantic search against the index, for sanity-checking — not the real hybrid retrieval layer (that's still TBD, see [specs/policy_storage.md](specs/policy_storage.md)).

`scan` and `build` can be run together as `ingest.py all`. `build` always does a full rebuild — cheap at ~40 documents, and keeps the index reproducible from `raw/` + `manifest.json` at any time.

If document metadata was collected in a spreadsheet before the files themselves were downloaded (as happened with the team's `Clinical-Policy-Corpus-Manifest.xlsx`), import it once with:

```bash
python -m backend.policy_store.import_corpus_xlsx /path/to/Clinical-Policy-Corpus-Manifest.xlsx
```

This upserts rows from the spreadsheet's "Final Corpus" sheet into `manifest.json` by id, carrying over the extra curation fields (`organisation`, `channel`, `format_number`/`format_name`, `doc_control_platform`, `document_date`, `date_checked`, `verified_open`, `notes` — see [specs/policy_storage.md §1.1](specs/policy_storage.md#11-curationprovenance-fields)). Entries whose source URL doesn't resolve to a confirmed file type get `format: "pending"` until the real file is downloaded and placed at the entry's `raw_path`. After this one-time import, `manifest.json` is canonical — edit it by hand or via `scan`, not by re-running the spreadsheet import as routine.

## Testing Retrieval

Once real files are downloaded into `data/policies/raw/` (each at the exact `raw_path` its manifest entry already has — rename the downloaded file to match, or update `raw_path`/`format` if it landed somewhere else), rebuild the index and run the retrieval smoke test:

```bash
python -m backend.policy_store.ingest build          # add --no-embed if torch/sentence-transformers isn't installed
python -m backend.policy_store.eval_retrieval         # add --no-embed to match
```

This checks only the "Initial retrieval" step from [specs/intelligence_logic.md §4](specs/intelligence_logic.md#4-steps-in-the-flow) — a raw question straight into `keyword_search`/`semantic_search`, no intent extraction and no CKAI-informed refinement (those are separate, later, and still-open pipeline steps). `data/policies/eval/retrieval_queries.json` holds ~15 hand-written clinician-style questions, deliberately paraphrased away from each document's actual title/text, each mapped to the doc id(s) it should surface — a "hit" means the expected doc appears anywhere in that method's top-k, not that it ranks first. It's a floor-level check (does the substrate contain and surface the right thing at all), not a substitute for the retrieval-scoring work that's still TBD.

Expect most/all of these to `MISS` until the corresponding real file is actually downloaded, placed, and indexed — the 4 entries the spreadsheet import marked `format: "pending"` will keep missing until their real file type is confirmed by hand.

If downloaded files don't land pre-named to match a manifest entry's `raw_path` (e.g. they're named `{row_number}_{org}_{title}.ext` for the team's own tracking), match them up first:

```bash
python -m backend.policy_store.reconcile_raw_files
```

This joins each file to its manifest entry via `source_row_id` (survives filename/slug drift) and updates `raw_path`/`format`/`date_collected` — safe to re-run as more files come in.

To see retrieved results in a browser instead of the terminal:

```bash
python -m backend.policy_store.retrieval_test_server   # add --no-embed to match a keyword-only index
```

Then open http://localhost:8020/ and type a question — [retrieval_test.html](retrieval_test.html) shows the keyword and semantic results side by side (title, section, score, text snippet) plus the full JSON response in a collapsed accordion, mirroring [local_api_test.html](local_api_test.html)'s pattern for the CKAI harness. Same scope caveat as above: this is `GET /api/retrieve` on the retrieval substrate only, not the eventual `POST /api/query` contract from [technical_spec.md §4](specs/technical_spec.md#4-backend-api-contract) — no CKAI, no intent extraction, no refinement.

## Current Status

- **Architecture drafted.** TypeScript front end (framework TBD) as a pure client, Python backend as a JSON API doing the CKAI call, policy retrieval, and prompt flow — see [specs/technical_spec.md](specs/technical_spec.md).
- **CKAI API confirmed and documented.** No API key required; access is gated by being on the Elsevier network/VPN. Full endpoint list, request schema, the mandatory nursing `orchestration_config`, and a real captured response shape are in [specs/ckai_api.md](specs/ckai_api.md).
- **End-to-end smoke test working.** [local_api_test.html](local_api_test.html) calls the real cert CKAI API (via [proxy_server.py](proxy_server.py), which works around both a CORS restriction and a local TLS trust issue) and renders the actual generated answer, with the full raw JSON available in a collapsed accordion for debugging.
- **Storage/indexing approach decided.** Raw files on disk + JSON manifest, normalized via an ingestion script, indexed into one SQLite file (FTS5 keyword search + stored embeddings for semantic search) — see [specs/policy_storage.md](specs/policy_storage.md). How retrieval scores/combines keyword + semantic, and how it's refined by the CKAI answer, is still open.
- **Intelligence-logic pipeline design decided.** A manually designed, per-experience pipeline of typed (Pydantic) steps — intent extraction, retrieval, CKAI call, retrieval refinement, then response creation (draft → citation validation → conflict check → formatting) — with agents explicitly deferred in favor of a fixed flow for reproducible eval. Uses open-source `pydantic` only, no hosted/SaaS observability. See [specs/intelligence_logic.md](specs/intelligence_logic.md). Response-creation prompt content itself is not yet designed.
- **Policy storage/indexing implemented and validated against real files.** `backend/policy_store/` (extraction, chunking, SQLite/FTS5 index, embeddings, keyword + semantic search) is indexing real downloaded PDFs/HTML — 21 of 23 corpus documents so far (2 not yet downloaded). The retrieval smoke test (`eval_retrieval.py` / `retrieval_test_server.py` + `retrieval_test.html`) hits 13/15 keyword and 12/15 semantic on hand-written clinician-style questions against real extracted content. Chunk size/overlap and embedding model choice are still placeholder defaults, to be tuned with more data and eval.
- **Not yet started:** the rest of the real Python backend (API endpoint, prompt flows), the real front end, the response-creation prompts, intent extraction, retrieval refinement from the CKAI answer, and the remaining exemplar policy files.

## Running The Test Harness

1. Start the local proxy (stdlib only, no install needed):
   ```bash
   python3 proxy_server.py
   ```
2. Serve this folder and open `local_api_test.html` in a browser, e.g.:
   ```bash
   python3 -m http.server 5500
   ```
   then visit `http://localhost:5500/local_api_test.html`.
3. You must be on the Elsevier network/VPN. Switch the Physician/Nurse tabs and ask a question — the generated answer renders directly, with the full JSON response collapsed below it.
